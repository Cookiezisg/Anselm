# EDGE-277 文档改名子树级联：红证据

- 日期：2026-09-01
- 现场：`/private/tmp/anselm-rig-formal-20260831-11/sessions/20260901-102346`
- 结论：停止，修复后重测

## 复现

在真实 App 打开三层文档树时，通过同一工作区的 REST PATCH 将根文档名称改为新值。后端返回成功，左侧 Library 树、Inspector 路径和后端文档路径都刷新为新值；但当前打开页的中心标题和 Inspector 标题仍保留旧值。

这违反了文档元数据更新后的单一视觉真相：用户看到的树、路径和当前页面互相矛盾。正文未丢失，问题限于已打开文档的元数据展示没有跟随树通知更新。

## 现场证据

- 五通道台架已收口，录屏和 backend/SSE/LLM/frontend 日志均保留在上述 session 目录。
- 本次 UI 输入过程中曾产生临时错误名称，随后已通过 REST 恢复；该输入交互不作为产品判断依据。
- 受控 REST 外部改名仍稳定复现标题滞后，因此问题定位为前端当前页元数据投影，而非后端级联或数据持久化错误。

## 修复方向

保留已加载正文和编辑器状态，只用最新 document-tree 行覆盖当前文档的名称、描述、标签、路径及其他元数据；当前页标题和 Inspector 标题均使用同一合并结果。修复后必须在新的真实 App 台架中重测并通过 L2-L5，才允许关闭本条。
