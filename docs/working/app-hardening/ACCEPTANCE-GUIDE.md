## ⚠️ A 类为什么**只能**从真 app 跑 —— 一次实测结论(2026-07-25)

有人(包括 AI)会想走捷径:不启动 GUI,直接跑一个 CLI 后端连上真实数据目录、用 curl 打 API 做验收。
**这条路走不通,而且它走不通是件好事。**

实测过程与结果:把真实数据目录(`~/Library/Containers/website.anselm.app/Data/.anselm`)**只读复制**到
临时目录、用另一个二进制启动后端 → 健康检查 200、真实 workspace 与受管 key 都能列出 → 发一条真实对话 →
回合失败,原因是:

```
apikey.Service.ResolveCredentialsByID: decrypt: aesgcm: open: cipher: message authentication failed
```

**这正是 [ADR 0008](../../decisions/0008-master-key-keychain.md) 主密钥设计在按预期工作**:凭证由 keychain
里的主密钥加密,而那把钥匙绑定签名 app;**另一个进程搬不走它**。换言之——

> **A 类每一项都必须从真正的 app 里跑。** 任何「用 CLI 或脚本代跑 A 类」的方案都会在解密这一步失败;
> 若某天它**不**失败了,那说明凭证边界破了,那本身就是最高优先级的安全缺陷。

(该实测只操作副本,原库未被触碰;副本与进程已清理。)

## A 类 · AI 可代跑(需真 app;恢复主树权限后)

### A1. 受管路由的图片端到端(**本轮修复的验收**)

> 🔴 **硬前置:网关必须先重新部署。** 生产网关 `api.anselm.website` 现在跑的是**旧代码**——它还不认相对
> lease 引用,而桌面端已改成发相对形。**在网关部署本轮提交之前,A1 必定失败**,且失败信息会是
> `image_url must be a base64 data URI`。这不是回归,是两仓未同批上线。**先部署网关,再跑 A1。**

```bash
make -C backend seed && make -C frontend app
```

在 app 里新建对话 → 附一张 **JPEG/PNG** 图片 → 问「这张图里有什么」。

**算过**:AI 正常描述图片内容;右岛工具卡无红;后端日志里能看到一次 media upload/complete,**且聊天请求里没有 base64**。
**算不过**:回合失败、或看到 `image_url must be a base64 data URI`(说明两仓未同批上线)、或看到 `MEDIA_UNAVAILABLE`(说明网关 `MEDIA_ENABLED` 没开)。
**成本**:一次 Qwen 图片调用(以你的免费档配额计)。

> ⚠️ **两仓必须同批上线**。桌面端现在发**相对** lease 引用,旧网关会拒;绝对形发给新网关同样会拒。

### A2. HEIC 降级(高危 2 的验收)

同上,但附一张 **HEIC**(iPhone 直出照片)。

**算过**:**回合不失败**,AI 回答里出现一句说明——大意是这张图的格式暂时无法准备、建议转成 JPEG/PNG/WebP 再发。
**算不过**:整个回合报错(那是修复前的行为)。
**成本**:一次文本调用。

### A3. 音频附件播放(A 片的验收)

附一个 `.mp3`/`.wav` → 发送 → 点消息里的音频卡播放 → 拖动进度条 seek。

**算过**:能播、能暂停/恢复、**seek 有效**(Range 请求正常);切到别的对话时播放自动停止。
**算不过**:点了不响、或 seek 后从头开始。
**成本**:零(纯本机)。

### A4. 长对话上下文治理

在一个对话里连续发若干条很长的消息(每条几万字符),直到跨过压缩线。

**算过**:全程**没有**用户可见的 `input too large` 类错误;对话仍能正确回忆最早提到的信息(说明摘要保住了要点)。
**算不过**:出现用户可见的上下文错误,或对早期信息完全失忆。
**成本**:若干次真实调用,**这是本清单里最烧配额的一项**——建议放在最后跑。

### A5. 麦克风状态机与权限流(**不含转写内容**)

空输入框 → 圆钮应是**麦克风**(仅当当前对话走 Anselm Auto;换成外部模型后应变回不可用并给出原因)→ 点它 → 首次会弹系统麦克风授权。

**算过**:授权弹窗出现;允许后进入录音态(有时长与电平波形);点停止后进入可编辑草稿、**不自动发送**;按拒绝则给出「去系统设置」的明确提示而非泛化失败。
**算不过**:按钮位置/状态不对、拒绝后落入泛化错误、或停止后直接发出去了。
**成本**:零到极少(不说话则几乎无音频时长)。

> 转写**准确率**不在此项——那需要真人发声,见 C3。

## B 类 · 需要密钥与预算(把 key 放进环境后 AI 可跑)

> 三个 make 目标都有**双门控**:缺 key 会安全跳过、**绝不产生计费**。跑之前先确认你愿意花这笔钱。

### B1. 真实 1M 长对话 eval

```bash
EVALS=1 EVALS_LONG_CONTEXT=1 make -C backend evals
```
另有 `EVALS_NATURAL_OVERFLOW=1` 跑「首次自然撞墙 → 学习后稳定治理」金标。
**需要**:`EVALS_KEY` / `DEEPSEEK_API_KEY`(经 `<repo>/.env` 或环境变量)。
**算过**:每轮 anchor 保真;至少一次 `observedContextRecoveries > 0`;**任何一轮出现 `status=="error"` 或非空 `ErrorCode` 即失败**;最终轮同时召回首尾 anchor 并等到 durable summary。
**成本**:真实长上下文调用,**本清单最贵**。

### B2. Qwen 图/视频/音频付费金标

```bash
EVALS_PROVIDER=qwen EVALS_KEY=… EVALS_BASE_URL=https://{WorkspaceId}.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1 make -C backend qwen-evals
```
**算过**:固定素材分别真实调用 Qwen3.7 图像/视频、Omni 音频;Qwen3.7 工具调用后有 `tool_result` 与最终续答。
**成本**:各模态各一次真实调用。

### B3. ASR 真 key eval(网关仓)

```bash
make qwen-asr-evals   # 需 EVALS_ASR_WAV 才要求真实转写文本,否则只做协议/连通 smoke
```

### B4. 生产 media lease 抓包

部署启用网关媒体配置后,在真实链路上抓一次完整的 create → chunk → complete → lease → provider fetch。
**算过**:聊天请求体里**没有**媒体字节;provider 拉取的是网关签发的短期签名 URL;结算后对象被回收。

### B5. 全模态产出真钱金标(WRK-082 批B/C/D)

代码与机械证据已收口(见 [`multimodal-output/README.md`](../../archive/multimodal-output/README.md) §0.2 的逐条核对);
下面四条是**只有真 key 能给**的那一半。**先确认你愿意花这笔钱**——每条都是真实计费调用。

```bash
# 前置:把 key 放进环境(任选其一即可跑对应那条)
export DASHSCOPE_API_KEY=…     # 图 + 语音 + 视频(wan)
export GEMINI_API_KEY=…        # 视频(Veo)
```

| 条目 | 怎么跑 | 算过的判据 | 大约成本 |
|---|---|---|---|
| **出图** | 真 app 里对话说「画一只戴帽子的猫」 | 图渲在对话里、点开是大图;附件行在库里、字节可下载 | 一张图(qwen-image ≈ ¥0.25) |
| **出语音** | 任一回复点「朗读」;**再点一次同一条** | 第一次出声;**第二次立即出声且 journal 无新计费行**——缓存命中是本条真正要证明的东西 | 一次合成(按字符) |

> 故它是四条里唯一「真钱只为再确认一次」的;前三条的真钱是**第一次**验证。

### B6. 价格卡对账(两笔已知的债)

网关的两张卡 ID 里带 `assumed-`,标记的正是这笔债:
`qwen-image-2.0-assumed-2026-07-27`(¥0.25/张)与 `qwen3-tts-flash-assumed-2026-07-27`(¥1/万字符)。
两者都取自第三方汇总——**官方定价页的表格在 JS 里,抓不到逐字数值**。

**怎么算过**:登录阿里云控制台核对这两个模型的实际单价,与卡里的 pUSD 数对上;对上就把卡 ID 的
`assumed-` 去掉、换成核对日期。**这是唯一一处代码里明说「这个数可能不对」的地方**,别让它一直留着。
